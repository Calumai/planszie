# 減脂紀錄網站系統文件

## Project Brief

### 專案目標

建立一個手機優先的減脂紀錄網站，用來快速記錄每日飲食、熱量、蛋白質、運動、體重與身體狀態，並用溫和但具體的陪跑回饋協助長期執行。

### 主要使用者

- 主要使用者：每天用手機記錄飲食與運動的減脂者。
- 使用情境：吃飯前後、運動後、睡前回顧、外食時快速估算。
- 使用限制：不希望輸入流程太細碎；手機上要能單手完成主要操作。

### 成功標準

- 10 秒內可以完成一餐熱量輸入。
- 可以用大按鈕計算機輸入或累加熱量。
- 可以用文字辨識先填入常見食材估算。
- 有 OpenRouter 或 OpenAI API Key 時，可以拍照辨識餐點並填入表單。
- 首頁可以看到今日熱量、剩餘可吃、運動消耗、宏量營養與歷史趨勢。
- 資料可以本機保存、匯出備份，並保留 Google Apps Script 同步路線。

## Style Guide

### 介面語氣

- 溫和、務實、陪跑，不羞辱、不恐嚇、不把食物絕對禁止。
- 強調「有記錄就有方向」，不要要求完美。
- 對失誤的回饋要導向下一餐回正軌。

### UI 原則

- 手機優先，常用動作放在底部導覽與大按鈕。
- 卡片維持 8px 圓角，資訊密度要適合每天重複使用。
- 熱量輸入使用大尺寸計算機按鈕，避免手機鍵盤造成摩擦。
- 顏色避免單一色系，使用綠、珊瑚、金、藍、紫作為狀態與操作區分。

### 資料呈現

- 對話整理與非精密秤重資料都要標示為估算。
- 首頁優先顯示今日決策需要的資訊，不堆疊過多說明文字。
- 歷史資料用趨勢感輔助，不把單日體重當成成敗判斷。

## Workflow

### 每日使用流程

1. 早上記體重與身體狀態。
2. 每餐用文字、拍照或計算機記錄熱量。
3. 運動後記錄類型、時間、消耗與膝蓋/小腿狀態。
4. 睡前看今日總結，確認明日最低標準。

### 飲食輸入流程

1. 選餐別。
2. 輸入餐點描述，或拍照上傳。
3. 按「辨識文字」或使用照片辨識。
4. 用計算機修正熱量。
5. 必要時用蛋白質/碳水/脂肪快速按鈕微調。
6. 加入今日飲食。

### AI 接手規則

- 優先保留現有本機儲存、備份、GAS 同步、PWA 和 GitHub Pages 行為。
- 新功能先確保手機主要流程可用，再擴充桌面版。
- 飲食估算要保守標示，不要假裝精準。
- 涉及醫療或藥物時只做紀錄與提醒，不替代醫療建議。

## Review Checklist

- [ ] 手機底部導覽固定在螢幕底部，沒有遮住主要按鈕。
- [ ] 新增飲食頁可輸入文字並按辨識填入估算。
- [ ] 計算機按數字、加號、清除、退格、填入都正常。
- [ ] 按「估」後直接輸入數字會覆蓋估算值；按加號才累加。
- [ ] 拍照上傳在沒有 API Key 時會給清楚提示。
- [ ] 歷史資料與已儲存每日紀錄仍可顯示。
- [ ] PWA 快取更新後不會長期卡舊 CSS 或 JS。
- [ ] `app.js` 與 `server.js` 語法檢查通過。
